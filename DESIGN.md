# DESIGN.md — дизайн-система KMF (для агентов)

Файл подключён в `CLAUDE.md` через `@DESIGN.md` и загружается в каждую сессию. Это **обязательные
правила**, а не справка: любая работа с вёрсткой, стилями, текстами интерфейса или Figma идёт по нему.
Люди смотрят дизайн в Figma; этот файл — перевод Figma в правила для кода.

При конфликте: макет в Figma (код `get_design_context` / `get_metadata`) > этот файл > скриншот.
Изменил дизайн-систему (компонент, токен, состояние, правило) — обнови этот файл в том же коммите.

## 0. Порядок работы — выполнять всегда

1. **Сначала Figma, потом код.** Любая визуальная правка (размер, цвет, состояние, новый блок или
   компонент) сначала вносится в UI-kit / макет «к вёрстке», затем переносится в код. Код не должен
   «опережать» макет.
2. **Не придумывать.** Чего нет в макете (раскрытое меню, состояния, пустые/ошибочные экраны, тексты)
   — спросить или предложить дизайн в Figma и согласовать, а не верстать «на глаз».
3. **Читать узел, а не картинку.** Размеры, отступы, gap, выравнивание, стили текста — из
   `get_design_context` и координат `get_metadata`. Скриншот — только для финальной сверки.
   Перед `get_design_context` загрузить навык `figma:figma-design-to-code`, перед `use_figma` —
   `figma:figma-use`.
4. **Переиспользовать.** Сначала искать компонент в `@/components/ui` и `blocks` (таблица в §4).
   Новый повторяющийся элемент — компонент в ките (доска, описание, варианты) → компонент в коде →
   витрина `/ui-kit`.
5. **Только токены.** Цвета, размеры шрифтов, отступы, радиусы — утилиты/переменные из §2.
   Hex, `px`-шрифты и произвольные цвета в классах запрещены (исключения — в §2).
6. **Тексты — по-русски, без англицизмов** (§8).
7. **Проверить** (§10): `/ui-kit`, `npm run check:layout`, Playwright-скриншоты 1440 и 360,
   lint/typecheck/format.

## 3. Визуальный язык

- **Острые углы.** Скругления только там, где они в ките: пилюли (CTA, «Заказать», тумблер).
- **Срез угла** (нижний правый) — фирменный приём, делается `clip-path`, не картинкой:
  карточка проекта desktop 101×65 (`88.5%` высоты → `76%` ширины), mobile 32×20;
  панели попапов 101×65 (md+); баннер и панель согласия 32×20 (md+). `box-shadow` клипается — для
  тени снаружи использовать `drop-shadow` на обёртке.
- **Линии со стрелками и точками** — CSS-компоненты `ArrowLine` и `StepDivider` (серая линия со стрелкой
  - красная линия с точкой). Под заголовком попапа/панели — `StepDivider short`.
- **Заголовки секций** — капс, `text-heading`. Номера шагов — `StepNumber`, `text-step-number`.
- **Фон секций:** белый; `bg-cream` — подвал, полоса под слайдером, панели попапов.
- **Фото и видео** — без скруглений, `object-cover` в плитках, `object-contain` в лайтбоксе.
- **Акцент один** — `accent-red`. Не вводить новые яркие цвета.

## 5. Состояния и анимации

- **Длительность 0.2s** для hover/цвета (`duration-200`), появление попапов — 0.3s.
- **Hover кнопок** (варианты `State=Hover` в ките): пилюля CTA, Outline, Dark, Sand — заливка
  `accent-red`, текст `text-inverse`, у рамок — `border-accent-red`. У ButtonCta и шапки hover на
  всей группе (`group-hover`): пилюля и квадрат реагируют вместе.
- **Квадрат со стрелкой** (`ArrowSquare`): при hover родителя `.group` стрелка поворачивается на 45°
  (↗ → →) вокруг центра квадрата, размер квадрата не меняется, красный темнеет на 10% заливкой.
  **Никогда** не анимировать CSS `filter` на картинках — дёргается на пиксель.
- **Ссылки:** hover — `opacity-70`. **Поля:** фокус — рамка `text-primary`.
- **Slider Arrows:** стрелка `accent-red`, когда в её сторону можно листать, иначе `bg-stone-light`;
  кружок стоит на активной стрелке, по клику перепрыгивает на нажатую (дуга, 0.35s), в конце ленты —
  на оставшуюся активную.
- **Video Tile:** hover — линии рамки дотягиваются до углов и замыкаются.
- **Шапка desktop:** сворачивается в мини-шапку (`layoutId` из `motion`), когда элемент с
  `data-header-compact` (на странице проекта — галерея) доходит до верха экрана; без маркера — после
  80px. Мини-шапка занимает место compact-bar из макета: в секциях с compact-bar оставлять отступ 41px.
  На главной мини-шапка стоит по центру: пункты меню и телефон съезжаются к центру и сворачиваются
  в иконку меню (лого + красная стрелка + меню).
- **Главная:** ленты превью первого экрана — бесконечный слайдер (крутится сам и листается
  перетаскиванием); `section-benefits` закрепляется у верха экрана (pin, как ScrollTrigger в GSAP),
  прокрутка листает Feature Item, фото справа меняется на каждый пункт; в `section-showroom` —
  видео. Подвал на главной — `bg-white` (на странице проекта `bg-cream`), срез карточек — clip-path.
- **Попапы:** fade затемнения + панель снизу вверх 24px (`animate-[popup-in_…]`, keyframes в
  `globals.css`).

## 6. Адаптив

- Макеты 1440 и 360, между ними — интерполяция токенами (`clamp`).
- Брейкпоинт `md` (768) — компоненты, шапка, подвал, попапы, баннер. `xl` (1280) — секции, чьи
  колонки не влезают уже (intro, галерея, слайдер проектов, двухколоночная форма в попапе).
  Указывать брейкпоинт в JSDoc компонента.
- Меняется только порядок блоков — один DOM + `grid-template-areas` (заголовок не дублировать).
  Раскладки принципиально разные — две ветки (`hidden xl:block` / `xl:hidden`).
- Отличия mobile, которые уже приняты: попапы форм и лайтбокс — на весь экран; «Весь отзыв» — лист
  снизу; баннер согласия — на всю ширину снизу; иконки шапки 32px.

## 7. Паттерны

- **Попап** — `popups/Popup` на `<dialog>`: `showModal`, Esc и клик по фону закрывают,
  `lockScroll()`, первичный фокус — крестик. `variant="screen"` (формы) или `"sheet"` (отзыв).
  Ширину задаёт `className`.
- **Открытие попапов ссылками:** `PopupHost` в layout перехватывает клики (фаза захвата — раньше
  `next/link`) по ссылкам на `#send-project` и `#showroom`. Новые CTA — просто ссылка
  `site.cta.href`. Новый попап — ключ в `popups` в `PopupHost`.
- **Лайтбокс** — `LightboxProvider items` вокруг галереи, `LightboxTrigger index` поверх плитки.
- **Согласие на текстовые файлы данных** — `popups/ConsentBanner` в layout, выбор в `lib/consent.ts`.
  Аналитику и рекламу подключать только при `hasConsent('analytics' | 'advertising')` и слушать
  `CONSENT_EVENT`. Панель настроек открывается ссылкой `site.consentSettings.href`.
- **Формы** пока не отправляют заявки (этап 2); экрана успеха в макете нет — не придумывать.

- Можно латиницей: товарные знаки и названия компаний (KMF, Blum, Profile-L, Instagram, WhatsApp,
  Telegram, Meta) и обязательная сноска про Meta. Названия изделий — по-русски.
- Согласие на обработку данных — только действием («Нажимая «Принять»…»), без «продолжая
  пользоваться сайтом».
- Технические идентификаторы (якоря `#showroom`, имена компонентов, ключи) — латиницей, это не текст
  интерфейса.
- Тексты, которых нет в макете, — черновик: помечать и согласовывать.

## 9. Иконки и ассеты

- URL ассетов Figma живут 7 дней — скачивать сразу, в репозиторий класть файлы.
- **Иконки:** `download_assets` по id компонента (format svg) → `public/icons/<name>.svg` →
  `node scripts/clean-figma-svg.mjs public/icons/<name>.svg` → добавить в `icons` в `Icon.tsx` с
  размером из Figma → открыть `/ui-kit`. Если у вектора в `get_design_context` отрицательные отступы
  (`inset-[-7.36px_…]`), экспорт может обрезать его — брать SVG из констант `get_design_context`.
  Если компонент в Figma отзеркален/повёрнут — проверить направление в коде (так было с `back-circle`).
- Иконки, которые меняют цвет или анимируются, — inline-SVG с классами `fill-*`/`stroke-*`
  (`ArrowSquare`, `SliderArrows`, `IconButtonClose`), а не `<img>`.
- **Фото:** `rawImages` (оригиналы), самый большой файл; дубли искать по md5. PNG-фото тяжелее ~1 МБ —
  в JPEG q90 без смены разрешения (sharp). Если в узле > 20 картинок — выгружать по дочерним узлам.
- Картинки из `public` в `next/image` — только через `asset()` из `@/lib/asset` (basePath `/kmf` на
  Pages); новые папки — в `images.localPatterns` в `next.config.ts`.
- Растягиваемые линии с точками/стрелками — CSS, не SVG с `preserveAspectRatio="none"`.

## 11. Грабли вёрстки

- `cn()` не сливает конфликтующие классы (`w-full` + `w-[564px]`). В базовых классах компонента не
  держать display/ширину/высоту, которые меняют снаружи, — выносить в проп с дефолтом
  (`ButtonCard size`, `StepDivider className = 'flex w-full'`).
- Tailwind 4: `rotate-*`, `translate-*` — отдельные CSS-свойства (`rotate`, `translate`), а не
  `transform`; у `<button>` preflight ставит `cursor: default` — указатель задаёт `Pressable`.
- `<dialog>` на мобильном: панель внутри — `shrink-0` в колонке, иначе длинная форма вылезает за
  фон; автофокус ставить на крестик, иначе браузер фокусирует первое поле и прокручивает вниз.
- Клики по хэш-ссылкам ловить в фазе захвата: `next/link` сам меняет хэш через `pushState`, без
  `hashchange`.
- Не держать `scrollbar-gutter: stable` на `html` — меняет ширину страницы в `check:layout`;
  компенсация полосы прокрутки — в `lockScroll()`.
- Страницы в `(site)` собираются статически (витрина Pages): без cookies/headers/серверных API во
  время запроса; то, что зависит от браузера (cookie согласия), — через `useSyncExternalStore` с
  серверным снимком, чтобы не было расхождения гидрации.

## 12. Правки в Figma через MCP

- Перед `use_figma` загрузить навык `figma:figma-use` (для экранов — ещё `figma:figma-generate-design`).
- Цвета — привязка к переменным (`setBoundVariableForPaint`), текст — стили (`setTextStyleIdAsync`),
  шрифт Manrope. Проверять: текст без переполнения, семейство шрифта, скриншот каждого фрейма.
- Состояния — варианты компонента (`State=Default/Hover`), не отдельные копии. Экземпляр не может
  менять трансформацию вложенного слоя (поворот) — для этого вариант у вложенного компонента.
- Переименование вариантов (`Style=Dark` → `Style=Dark, State=Default`) сохраняет связь экземпляров.
- Замена текста с сохранением стилей: `insertCharacters(i + old.length, new, 'BEFORE')` +
  `deleteCharacters(i, i + old.length)`, не присваивание `characters`.
- `clone()` кладёт копию в родителя оригинала; если оригинал в секции — проверить, что копия туда
  попала. Секции не растут сами — подгонять размер под содержимое, чтобы не перекрывались.
- У описаний компонентов (`description`) — размеры, токены и поведение; для экранов — заметки рядом
  с фреймами «к вёрстке».
