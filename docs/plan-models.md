# Как подготовить 3D-модель плана проекта

Инструкция для блока «План проекта» (этап 3): как из документации дизайн-проекта получить GLB по
ТЗ KMF и посмотреть его в просмотрщике. Отработано на тестовом проекте «ЖК Новое Медведково»
(Мытищи, пр-т Астахова, 14Б): квартира 82 м², 9 зон, 19 изделий KMF, 11,9 тыс. треугольников, 2,2 МБ.
Сборка с нуля по этой инструкции — 1–2 часа, почти всё время уходит на расстановку мебели.

Эталонные скрипты — [`scripts/plan3d/`](../scripts/plan3d/): общие `extract_plan.py`, `kmf_lib.py`,
`build.py`, `viewer.html` и комнаты тестового проекта `room_kitchen.py`, `rooms.py`.

## 1. Что получаем

- `<проект>.glb` — модель по ТЗ: 1 ед. = 1 м, Y вверх, начало координат — центр квартиры на уровне пола.
  Иерархия: `shell` (стены, окна, двери, коридор) и `zone--<ключ>` → пол `floor-<ключ>`, готовая
  мебель, предметы `item--<ключ>` → один склеенный меш изделия.
- У каждой зоны и предмета — свойство `title` (русское название). В GLB оно уходит в `extras`,
  в three.js это `object.userData.title`. Его показывает плашка при наведении.
- `<проект>.blend` с упакованными текстурами, `<проект>-keys.txt` — список ключей, `renders/`.
- `viewer/index.html` — просмотрщик для проверки (не сайт): контуры, AO, подсветка, плашка.

| Что                | Где / как                                                                            |
| ------------------ | ------------------------------------------------------------------------------------ |

по сокету.

## 3. Входные данные

Из папки проекта от KMF / дизайнера нужны:

- **«Часть 1. Техническая документация» — векторный PDF** (выгрузка из ArchiCAD, `GSPublisher`).
  Главный источник: геометрия снимается из векторов с точностью до миллиметров, обводить ничего не нужно.
  Номер листа в штампе = номер страницы PDF − 2 (обложка и записка без номеров).
- **«Часть 2. Визуализации»** — цвета и членение фасадов. Картинки растровые, берём только «на глаз».
- **Спецификации** — какая мебель от фабрики (поставщик «КОНСТАНТА» / «по образцу»), а какая готовая.
- Архив `.pla` — это ArchiCAD (заголовок `ROF FDB`), Blender его не откроет. Не нужен.

Листы «Части 1», которые используются:

| Лист (страница PDF)               | Что берём                                                             |
| --------------------------------- | --------------------------------------------------------------------- |
| Обмерный план (стр. 6)            | высоты подоконников и проёмов, высота потолка, проверка площадей      |
| План монтажа (стр. 8)             | стены: несущие, существующие перегородки (штриховка), новые (зелёные) |
| План дверных проёмов (стр. 10)    | двери (петля, полотно, дуга), окна (оранжевые линии)                  |
| План расстановки мебели (стр. 13) | **база координат**, прямоугольники и подписи мебели, экспликация      |
| План полов (стр. 25)              | контуры комнат и покрытия: ламинат, керамогранит, кварцвинил          |
| Развёртки стен (стр. 27–33)       | высоты и членение изделий на стенах                                   |

## 4. Порядок работы

### 4.1. Папка проекта

`D:\Desktop\KMF\<проект>\` (латиница, например `mytishchi-astakhova`), внутри `scripts/` — копия
`scripts/plan3d/`, `textures/`, `renders/`, `viewer/index.html` (из `viewer.html`).

### 4.2. Масштаб и база координат

- Масштаб листов 1:50 → **1 pt = 17,639 мм**. Проверить по известному размеру: глубина комнаты в pt ×
  17,639 должна совпасть с размером на обмерном плане (в тесте 390,7 pt → 6892 мм при 6891 на плане).
- База — лист расстановки мебели (стр. 13): `X0, Y0` в `extract_plan.py` — точка в pt, которая станет
  x=0, y=0 плана (в тесте — угол гостиной). Координаты плана: мм, x вправо, y вниз (к югу).
- **Листы свёрстаны со сдвигом.** План на разных листах стоит в разных местах страницы. Сверить bbox
  несущих стен (заливка `0.31`) на каждом листе и задать поправки `DX_MONTAGE`, `DX_FLOORS` (в тесте
  +14,17 pt и −5,67 pt). Без этого двери и окна уезжают на 250 мм.
- Центр квартиры (`ORIGIN_X`, `ORIGIN_Y` в `kmf_lib.py`) — середина bbox несущих стен в мм плана.

### 4.3. Слои PDF (цвета заливок и линий ArchiCAD)

| Слой                          | Как нарисован                                                  |
| ----------------------------- | -------------------------------------------------------------- |
| Несущие стены                 | заливка `(0.31, 0.31, 0.31)`                                   |
| Новые перегородки (монтаж)    | заливка `(0.51, 0.81, 0.56)`                                   |
| Существующие перегородки ПГП  | только штрихи 45°: серые линии ~4×4 pt, без контура            |
| Конструкции из ГКЛ            | заливка `(0.5, 0.5, 0.5)`                                      |
| Мебель на плане расстановки   | заливка `(0.87, 0.85, 0.82)` + подписи текстом                 |
| Пол: ламинат / плитка / винил | `(0.71, 0.64, 0.36)` / `(0.59, 0.79, 1.0)` / `(1.0, 0.4, 0.0)` |
| Двери и окна                  | оранжевые линии `(1.0, 0.4, 0.0)`: полотно, дуга, рамы         |

Если в новом проекте цвета другие — посмотреть `Counter` заливок на странице (`page.get_drawings()`).

### 4.4. Стены и полы — `extract_plan.py`

```bash
cd D:\Desktop\KMF\<проект>\scripts
python extract_plan.py   # → ../plan.json, ../walls.npy, ../zones.npy, ../kinds.npy, renders/debug-*.png
```

- Маска стен на сетке 0,5 pt (≈9 мм): несущие + новые + bbox штрихов (они перекрываются и дают сплошную
  полосу). Мелкие обрывки (откосы в проёмах) удаляются фильтром площади.
- Зоны пола: полигоны с листа полов → правила «какая комната» (в `ZONES`, по центру bbox и линиям
  раздела — например, спальня / гардеробная по линии перегородки, гостиная / коридор по линии стены).
  Комната без мебели KMF (коридор) — не зона, её пол уходит в `shell`.
- Пол отделки не доходит до стен (облицовка, ниши под ванной) — зоны дорастают до стен заливкой, которая
  не проходит сквозь стены и не выходит за внутренний контур наружных стен.
- **Обязательно открыть `renders/debug-walls.png` и `debug-zones.png`** — дыры, полосы и протечки видны
  сразу.
- На выходе — прямоугольники (`walls`, `zone_rects`), из них Blender собирает стены и полы.

### 4.5. Окна, двери, мебель

- **Окна** (`WINDOWS` в `build.py`): x от–до проёма, полоса стены по y, отметка подоконника с обмерного
  плана, ось стекла. Подоконник — белый блок до отметки, рама графит, стекло до среза стены.
- **Двери** (`DOORS`): с листа дверей — петля, конец полотна закрытым (конец дуги) и открытым (линия
  полотна). Сборщик ставит полотно приоткрытым на 70° (ТЗ: не перекрывать проходы).
- **Мебель:** вывести прямоугольники и подписи с листа 13 (последний блок `extract_plan.py` пишет их
  в `plan.json`), сопоставить со спецификацией. Изделия KMF — в `rooms.py` / `room_<комната>.py`
  функциями `box`, `fronts_row` (фасады с зазором 3 мм поверх корпуса цвета `kmf-gap`), `split`.
  Готовая мебель — своя библиотека в `kmf_lib.py` (`soft_block`, `dining_chair`, `plant`): простые формы
  с фаской, нейтральные цвета, одна визуальная семья. Модели Poly Haven не подошли — винтаж,
  фотореализм и текстуры 8K.
- Ключи и подписи: `L.empty('zone--kids', None, 'Детская')`, `item(zone, 'desk-01', 'Рабочий стол')`.
  Ключи даёт менеджер KMF; в тестовом проекте придуманы.

Типовые высоты, если в развёртках нет своих:

| Элемент                 | мм                              |
| ----------------------- | ------------------------------- |
| Срез стен               | 1300 (ТЗ: 1200–1500)            |
| Верх высокой мебели KMF | 2640 (потолок 2740 − опуск)     |
| Цоколь / низ фасадов    | 0–100                           |
| Столешница              | 860–900                         |
| Верхние шкафы           | 1500–2640, глубина 350          |
| Подвесные тумбы         | 150–450 (ТВ), 300–850 (санузел) |
| Столы                   | 730–760                         |
| Двери                   | 2100                            |

### 4.6. Сборка и выгрузка в Blender

Через MCP `blender` → `execute_blender_code`, **сборка и выгрузка — одним вызовом** (пространство имён
между вызовами MCP не сохраняется):

```python
exec(open(r'D:\Desktop\KMF\<проект>\scripts\build.py', encoding='utf-8').read())
print(export())  # {'keys': 28, 'tris': 11888, 'mb': 2.16, 'materials': 19, 'dupes': []}
```

`build.py` пересобирает сцену с нуля (≈1 с), поэтому любую правку вносить в скрипт, а не руками в
Blender. Проверить вывод `export()` по ТЗ: треугольников ≤ 300 тыс., файл ≤ 50 МБ, материалов ≤ 20,
`dupes` пуст. Посмотреть результат — MCP `look` (`mode: camera` и `views: ["top"]` для сверки с планом).

### 4.7. Просмотр

```bash
cd D:\Desktop\KMF\<проект>
python -m http.server 8090 --bind 127.0.0.1   # → http://127.0.0.1:8090/viewer/
```

Просмотрщик: ортокамера (стартовый ракурс 45° / 35°, вращение по кругу, снизу не заглянуть), контуры
шейдером по глубине и нормалям, GTAO, мягкие тени, подсветка по правилам ТЗ (предмет — только он,
остальное в комнате — вся зона, `shell` — ничего), курсор и плашка с `title` в стиле проекта.
Проверка без глаз — одноразовый Playwright-скрипт из папки сайта (см. CLAUDE.md, «Окружение»).

### 4.8. Подключение к сайту

- GLB положить в `public/` (сейчас `public/plan-demo/<проект>.glb`), в данных проекта
  (`src/data/projects.ts`) заполнить `plan: { model, facts }` — путь к GLB и параметры справа
  (тип, стиль, бюджет, срок). Блок `PlanBlock` берёт всё остальное из самой модели:
  - **вкладки** — по одной на каждую `zone--<ключ>`, порядок задаёт `ZONE_ORDER` в `PlanBlock.tsx`
    (незнакомые ключи — в конце);
  - **подписи** — из `title` (extras), без него показывается ключ;
  - **список изделий** зоны — её `item--…`; **габариты** в карточке — по bbox изделия в модели.
- Для каждой зоны нужна иконка `public/icons/plan-zone-<ключ>.svg` (28×28, линия 1,5, `#4C4C4C`).
  Новый тип зоны — сначала иконка в Figma (секция `137:2` файла KMF-to-dev), потом файл.
- Цена, фото, эскиз и материалы изделия в карточке появятся из CMS — в GLB их не класть.
- Тестовая страница с блоком — `/projects/[slug]/plan-3d/` (только проекты с `plan`).

## 5. Точность

Сверка тестового проекта:

- **Стены и проёмы** — из векторов, погрешность сетки ±9 мм. Сумма площадей комнат в модели 82,89 м²
  против 82,57 м² на обмерном плане (+0,4%).
- **Площади комнат в модели на 5–15% больше экспликации листа 11** — это нормально: модель идёт по
  черновым стенам (лист монтажа), а экспликация — по чистовым (минус штукатурка, ГКЛ, плитка, короба).
  Мебель стоит по чистовым граням, поэтому от черновой стены до неё остаётся 20–50 мм — на виде не заметно.
- **Положение и габариты мебели в плане** — из прямоугольников листа 11, точно.
- **Приблизительно:** высоты изделий (из развёрток, иначе — типовые), внутреннее членение (число фасадов,
  полки, ниши), мебель, которой нет среди прямоугольников плана (в тесте — кровать в детской, по картинке
  листа), положение декоративной перегородки. Окна — подоконник с обмерного плана, рама упрощённая.

## 6. Грабли

- **Не строить стены и полы сеткой с `dissolve_limit`** — около миллиона граней вешают Blender на минуты
  (вылечить можно только закрыв его). Стены и полы — из прямоугольников, контуры рисует шейдер просмотрщика.
- После `importlib.reload` модулей комнат старое `kmf_lib` в памяти Blender даёт `ImportError` —
  в `build.py` библиотека перезагружается первой.
- Узел `Background` в Blender по умолчанию серый `0.8` — цвет фона задавать явно.
- В `numpy` для сдвигов маски не использовать `np.roll` — он переносит значения через край сетки.
- Белые стены на белом фоне теряют контур: в рендере — фон `bg-cream`, в просмотрщике — контуры шейдером.
- Одинаковые имена декора в разных комнатах дают хвосты `.001` — давать уникальные (`toilet-2`).
- С ракурса по умолчанию часть интерьера закрывают высокие изделия KMF (они по ТЗ не срезаются) —
  проверять вид с разных сторон.
